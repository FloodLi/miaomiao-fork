## 偏红偏黄修正候选（2026-09-12）

用户接受独立工作区布局后反馈略偏红偏黄。处理模块增加可选`neutralProtection`（0至100，通用默认0），仅本地样稿ID34色彩模式默认35；生产v3未增加该控件或默认强度，其他型号沿用原路径，未生成新的测试固件。

依据原始像素的色度差及相对饱和度，用平滑权重抑制低饱和度区域的红黄覆盖率，将减少的部分重新分配到黑白，保持软件参考色板的平均线性亮度。绝对色度差16至96、相对饱和度0.25至0.75之间平滑衰减；高饱和度暗色仍保护，不采用扩大硬阈值将浅色直接变灰。

默认35只作温和候选，真实浅红/浅黄也可能变淡；0恢复原算法。传输RGB墨色编码不变，已处理PNG经默认中性路径复核不变。17项偏色主机检查及原照片10项浏览器检查通过；无实屏色板标定、LUT或电压更改，实际颜色仍待同图同光照对比。

## ID34 一体化编辑器 v3

本节为历史ID34 v3入口；当前所有面板已统一到上方多屏工作区，下方预设和大图窗口仅保留作历史对照。

- 选择图片后，桌面左侧为画布，右侧320px参数栏独立滚动；顶部文件、撤销/重做、上传始终可见。“放大”移动整个编辑器，包含全部参数，Esc关闭后保留状态。手机竖屏固定上方预览并滚动下方参数，横屏优先左右布局。
- 只有色彩、黑白、文字三种输出模式。默认亮度0、对比度100%、伽马1、暗部0、饱和度100%、锐化0；色彩/黑白使用100%柔化点阵，文字按128阈值二值化并禁用点阵、锐化和暗部提升。
- 色彩和黑白共享线性亮度处理；黑白仅允许黑白墨色。暗部0至100使用`L'=L+s*L*(1-L)^2`，只在用户调节时提升暗部，纯黑白端点保持。常用调节与高级区按模式隐藏不适用项。
- 各模式分别记住调色值，切换不重置构图。单项、调色、构图各有重置；一次滑块或裁剪拖动记为一步，撤销/重做最多50步，只保存参数快照。
- 完整显示、铺满裁剪、拉伸三种适配保留；铺满时可在“构图”工具中拖动并作1至4倍构图缩放。中心以旋转/镜像后坐标归一化保存并约束不露白。适应、100%、25%至200%观看缩放及平移不改上传内容。
- 更换图片清除上一图的构图、观看位置和历史，保留调色；坏图清除可上传状态。处理源图使用读取型Canvas上下文，避免重复变换时GPU/CPU重采样差异被误差扩散放大。

处理实现位于`web/image_processor.js`，窗口回退和Worker共用一个函数。队列最多一个在途和一个可替换的最新任务；同一原图结果按版本递增展示，旧原图和倒序结果丢弃。处理中禁用上传，PNG编码后再检查epoch/revision，实际发送完整原始点阵而非面积平均显示缓冲。Worker异常或10秒无响应后改用同一函数回退；处理错误不允许继续发送旧帧。

设置保存为`upload_editor_v3_panel_34`，原键不覆盖。旧照片/色彩/动漫/柔和映射色彩，灰度映射黑白，文字映射文字，命名风格恢复中性值；自定义只导入可兼容的调色数值，旧构图不套到新图片。原图不写入浏览器存储。

新增`GET /image_processor.js`，沿用已有静态脚本的响应头；现在为81条HTTP路由、12个HTML、2个JS、1个PNG。上传API、面板驱动、分区、字体、电压和LUT不变。软件预览不是实屏测色仿真，真实色差与默认画质仍需同图同光照验收。

## 7.5 寸彩色层次测试

### 入口与预览

2026-09-10 按用户确认，ID34删除旧“照片”按钮，将“彩色照片”改名为“色彩模式”，只保留一个彩色入口。内部 `colorphoto` 键不变；原命名 `photo` 配置迁移到新默认参数，原 `custom` 手动参数保留，其他面板入口不变。下方早期记录中的“彩色照片”指现在的色彩模式。

整体预览使用独立显示画布：从原始面板点阵在线性光空间做可分离的面积平均，并按视口与设备像素比设置显示尺寸，不只依赖浏览器CSS缩小。原始 `epdPreview` 画布仍保留800x480像素供1:1查看及验证，显示画布 `epdPreviewFit` 绝不参与上传。1:1按原始像素显示，可在框内滚动；切换视图、调整窗口及放大不会改图像处理参数或上传PNG。它不是实屏颜色仿真，屏幕反射、环境光和参考墨色的差异仍存在。

上传页桌面宽度上限扩大至1380px，预览放到参数上方，横屏预览上限至少960px；另有“放大”模态窗口，支持Esc关闭与焦点、页面滚动恢复。保留其他页面宽度不变。针对用户1280x960原图，在1440视口验证主预览宽925px，手机及横屏无页面横向溢出；本地截获实际上传POST，PNG与面板点阵逐像素一致。该结论不等于已完成物理墨色校准。

当前版本处理原图时使用“色彩模式”；历史输出目录里要求点击“照片”的说明针对旧版本，保留供追溯，不代表新版还有该按钮。

### 点阵纹理优化

2026-09-10 第二轮新增“点阵排列”：标准扩散保留首轮输出，柔化纹理在墨色选择时加入固定空间散列产生的阈值扰动。只改变选点次序，不把扰动加入源RGB、目标混色比例或传播误差；纯色端点、中性色门限和四色色板不变。没有生成或声称使用经过优化的蓝噪声纹理。

点击“彩色照片”预设默认使用柔化纹理；旧保存配置缺少 `dotPattern` 时仍恢复标准扩散，手动选择及自定义参数会单独保存。关闭抖动时扰动也关闭。该控制仅在ID34、四色配色、彩色层次模式下显示，4.2寸及其他模式不受影响。

这是对现有误差扩散的阈值调制，方法背景可参见[阈值调制与误差扩散研究](https://uwspace.uwaterloo.ca/items/e0d6bc8b-6e72-46f3-8bde-90447781588f)。本项目采用有限幅度、确定性的实现，并非复现该论文全部算法。相同图片和参数每次产生相同像素，预览与导出一致。

纹理回归使用15组96x96均匀混色块，取中心64x64区域，测量水平、垂直及两条对角方向2至12像素延迟的最大正相关，比较其均值；同时约束墨色比例变化。指标只用于识别规则重复纹理，不是实屏画质评分，也不证明所有图片都更好看。

用户已提供首轮彩色层次和旧色块模式的实屏照片：彩色层次能呈现更多红黄过渡，但规则点阵明显。照片非测色环境，不能作为电压、LUT或精确色板校准依据；本轮柔化纹理尚待新的实屏对照。

### 色彩处理

2026-09-10 新增仅限 ID34 的“彩色照片”预设及“色彩处理”选择：
“色块优先”保留既有算法，“彩色层次”让四色点阵共同表现明暗和颜色变化。
首轮曾保留已有照片预设、自定义设置和 ID37 的输出；后续ID34命名预设合并规则见上方“入口与预览”，自定义设置和ID37仍保留。

- 使用线性 RGB 参考色板，把源颜色投影到四色可表达的混色范围，再对四种墨色的覆盖比例做蛇形 Floyd-Steinberg 误差扩散。
- 新模式将源中性色保护收窄到 RGB 最大最小差不超过2，避免旧算法的20级保护范围吞掉浅红、浅黄；精确黑白和中性文字仍不染色。
- 饱和度、亮度、对比度、伽马、亮度锐化及抖动强度可调；不适用的红黄提取阈值和黑白阈值隐藏。选择黑白配色时使用既有黑白路径。
- 色板为软件参考值，不是实屏测得的反射率；蓝绿等色域外颜色无法准确还原。点阵增加的是视觉层次，不是单像素原生颜色数。
- 这项新增模式在浏览器处理原图，导出面板尺寸 PNG 后由固件直通；直接通过 API 提交普通 JPEG/PNG/BMP 仍走原有固件备用算法。

`test/web/jd75_color_regression.js` 可重复生成800x480、8行16列的色阶原图及新旧处理图。
前六行为红白、黑红、黄白、黑黄、红黄、黑白的参考混合；后两行为肤色及蓝绿限制参考。
此前简单线性 RGB 最近色扩散曾使浅红偏黄，已改为先约束混色比例；测试同时检查各色阶顺序、色差和错误黄色覆盖比例，不能只看总体平均误差。

## 处理边界

- 先按源像素判定中性灰，再做误差扩散；颜色不受邻近扩散误差影响。
- 蛇形扫描交替处理每行，减少单向纹理。照片重视层次，文字预设重视边缘清晰。
- 网页只对亮度锐化，避免灰边因彩色邻居而染色；原始透明像素先合成到白底。
- 网页预览和上传PNG使用同一转换函数。符合面板尺寸的墨色PNG在固件中直通，不二次抖动。
- 直接提交普通JPEG/PNG/BMP时使用固件备用配置，结果不保证与浏览器缩放和参数调整逐像素相同。
- 日历、时钟及其它内置页面不变；其它面板的量化路径不变。

## 实屏对比

用同一张原图分别选择照片、黑白照片和纯黑白，检查暗部层次、灰色是否染红黄、细线和文字清晰度。
先以默认全刷对比，记录面板ID、选择的预设和实际照片。旧图库中的已量化PNG不能恢复原始色阶，应重新上传原图。
自动灰阶块和边框测试仅验证算法，不证明实屏没有颗粒、残影或色差。
